# Сборка и публикация в SharePoint

## Принцип

Исходный код разделён только в контуре разработки:

- `src/index.template.html` — структура страницы;
- `src/app.css` — оформление;
- `src/app.js` — данные, расчёты и интерфейс.

Перед публикацией файлы объединяются в один автономный `index.html`. SharePoint не загружает и не исполняет файлы из `src`, `scripts` или `tests`.

## Контур выпуска

1. Изменения вносятся в файлы `src`.
2. Выполняется `python3 scripts/build_standalone.py`.
3. Выполняется `python3 scripts/build_standalone.py --check`.
4. Выполняется `python3 scripts/validate_model.py`.
5. В GitHub публикуются исходники, проверки и собранный `index.html`.
6. Для SharePoint пользователь скачивает только проверенный `index.html` и размещает его по согласованному пути.

## Выгрузка рабочих данных

Приложение не записывает данные прямо в SharePoint. При выходе из режима редактирования оно скачивает файлы только для изменённых областей: книгу каждого изменённого подрядчика, затем общий `config.json`, если менялись перечень/название подрядчиков, ссылка на книгу или общая единица отображения. Ручные кнопки скачивания доступны отдельно. Изменение только договора не создаёт новую копию общего конфига; просмотр без изменений не скачивает файл.

| Данные | Файл после скачивания в «Загрузки» | Размещение относительно приложения |
|---|---|---|
| Общий перечень и ссылки | `config.json` | `config/config.json` либо путь, заданный параметром `?config=` |
| Договоры, версии, назначения KQ-2 | `<подрядчик>_model_<дата>.xlsx` | Файл по прямой ссылке `contractors[].fileUrl` в общем конфиге; рекомендуемый каталог `data/contractors/<id>/models/` |
| Экспорт детальной модели | `model_<номер договора>.csv` | Аналитический результат для пользователя; место хранения определяется рабочим регламентом проекта |
| Автономное приложение | `index.html` | Согласованное место запуска в SharePoint |

После размещения новой книги подрядчика её прямая ссылка должна быть записана в `config.json`, иначе при следующем открытии загрузится старая книга. Путь публикации в конкретной библиотеке SharePoint и её политика для HTML требуют пилотной проверки; относительные пути выше описывают текущую структуру проекта, а не утверждённый адрес SharePoint.

## Ограничения безопасности

- В готовом HTML нет ссылок на внешние JS и CSS.
- Сборка и тесты не выполняются в SharePoint.
- Автономные скрипты разработки не загружаются пользователем как часть приложения.
- Конфиги и Excel остаются внешними данными по разрешённым относительным путям.
- Перед выпуском GitHub Actions проверяет соответствие `index.html` исходникам.

## Откат

Для возврата используется архив `model-backup-2026-09-23-pre-architecture.zip` либо конкретный подтверждённый GitHub-коммит. Частичное смешивание файлов разных версий запрещено.
