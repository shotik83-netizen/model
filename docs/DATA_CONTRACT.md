# Контракт данных финансово-экономической модели

## Назначение

Контракт фиксирует минимальные требования к данным без изменения существующей структуры документов. Excel-файлы и относительные пути остаются источниками истины, а приложение преобразует их во внутренние сущности.

## Уровни данных

| Сущность | Уникальный ключ | Обязательные связи |
|---|---|---|
| Подрядчик | `contractorId` | договоры, файл актуальной модели |
| Договор | `contractorId + contractId` | номер, наименование, версии |
| Версия | `contractorId + contractId + versionId` | дата, валюта, курс, параметры и ряды |
| Работа BOQ | `source + item_code` | наименование, единица, договорный объём |
| Группа KQ-2 | `kq_code` | работы BOQ и строки КСГ |
| Строка КСГ | `work_id`, при отсутствии — стабильный составной ключ | KQ-2, работа, период, объём |
| Ресурс/затрата | `expense_type + resourceId` | количество, ставка, период, вид затрат |
| Первичный документ | `contractor + contract_number + document_number + document_date` | сумма, валюта и дата |

## Денежные значения

Каждое денежное значение интерпретируется только вместе с:

- валютой источника;
- валютой договора;
- курсом конкретной версии;
- признаком НДС;
- единицей представления.

Рублёвый эквивалент не хранится как независимая несвязанная сумма. Он рассчитывается из исходной суммы и курса версии. Переключение представления не изменяет исходные данные.

## Совместимость

1. Физические имена и расположение существующих документов не меняются.
2. Отсутствующие идентификаторы формируются детерминированно из стабильных полей.
3. Исходные заголовки сопоставляются через `config/source-mapping.json`.
4. Неоднозначное автоматическое сопоставление требует подтверждения и не должно молча попадать в расчёт.
5. Новая версия схемы должна иметь функцию чтения предыдущей поддерживаемой версии.

## Реализация в приложении

- `src/data-adapter.js` нормализует валютный контекст, числовые значения, месячные ряды и устойчивые ключи.
- `src/calculation-core.js` выполняет независимые денежные преобразования и факторный мост.
- Оба модуля встраиваются сборщиком внутрь единого `index.html`; SharePoint не загружает их отдельно.
- Интерфейс использует тот же валютный контекст версии, что и расчётное ядро.

## Критические проверки

- `config.json` содержит уникальные идентификаторы подрядчиков и существующие файлы моделей.
- Каждый файл модели является корректной книгой XLSX и содержит лист `_DATA`.
- Каждая версия имеет распознаваемую валюту и положительный курс для валюты, отличной от RUB.
- Обязательные BOQ и КСГ существуют и имеют настроенное сопоставление обязательных полей.
- Для факторного анализа количество и ставка не подменяются готовой суммой.
