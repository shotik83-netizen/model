# Карта источников и расчётов финансово-экономической модели

Дата актуализации: 2026-09-22  
Связанные задачи: FM-2026-007, FM-2026-008, FM-2026-010

## Контроль цепочки BOQ → KQ-2 → КСГ

1. Каждая исходная строка BOQ получает `sourceKey` и нормализованный `kqCode`.
2. Укрупнение KQ-2 выполняется суммированием количества, стоимости, трудозатрат и машино-часов.
3. Цена KQ-2 рассчитывается как `стоимость BOQ группы / объём BOQ группы`.
4. Каждая строка КСГ получает устойчивый ключ, нормализованный код KQ-2 и ряд из 12 месячных объёмов.
5. Объём КСГ равен сумме 12 месячных значений; ставка назначается только при точном сопоставлении KQ-2.
6. Контроль объёма рассчитывается как `объём КСГ − объём BOQ` и не используется для автоматической корректировки источников.
7. Несопоставленные строки КСГ исключаются из стоимостной оценки до устранения причины сопоставления.

Контроль сохранения: сумма стоимости детальных строк BOQ должна равняться сумме стоимости укрупнённых KQ-2. Отображаемое округление не участвует в проверке.

## Проверенные источники Excel

| Источник | Назначение в приложении | Ключевые поля | Статус интеграции |
|---|---|---|---|
| `BOQ` | Контрактные объёмы, расценки СМР и МТР, трудозатраты, связь с KQ | Код и название позиции, единица, количество, ставки, KQ | Расценка BOQ может быть назначена месячному ряду KQ-2; выполнение рассчитывается как объём × расценка |
| `KQ` | Нормализация BOQ до аналитических групп KQ-1/KQ-2 | Код KQ, название, иерархия | KQ-2 используется как уровень агрегирования физического объёма и расценки |
| `КСГ` | Помесячные физические объёмы и график производства | KQ, работа, план/факт, даты, месячные колонки | Физический объём импортируется в ряд «КСГ / KQ-2» и показан в технико-экономических показателях |
| `Персонал ` | Основной и косвенный персонал | Подрядчик, категория, работа, вид персонала, календарные значения | Ряды основного и вспомогательного персонала разделены; назначение выполняется через карту источника |
| `Техника` | Количество и загрузка техники | Подрядчик, тип, наименование, работа, календарные значения | Машино-часы импортируются отдельным месячным рядом и участвуют в расчёте техники |
| `Первичка в вал.контракта` | Фактическое выполнение, расходы, зачёт аванса, план и факт оплаты | Подрядчик, договор, вид расхода, документ, дата, суммы без/с НДС | Поля настроены; требуется приоритет факта над расчётным прогнозом |
| `Платежи` | Фактические денежные выплаты | Дата, подрядчик, договор, сумма, вид оплаты и расхода | Поля настроены; требуется распределение по статьям расходов |
| `Факторинг` | Фактическое и плановое финансирование | Договор, документ, банк, период, сумма | Поля настроены; включение в денежный поток есть |

## Расчётные зависимости

| Результат | Источник / параметр | Расчёт | Состояние |
|---|---|---|---|
| Физическое выполнение | КСГ | Сумма плановых или фактических объёмов по KQ-2 и месяцу | Реализовано отдельным рядом; исходная детализация сохраняется во внешнем файле подрядчика |
| Доход от работ | КСГ + BOQ + KQ-2 | Физический объём × соответствующая расценка BOQ; при отсутствии обоих рядов используется явно помеченный ручной денежный ряд | Реализовано с прозрачным резервным режимом |
| Прямой ФОТ | Основной персонал | Численность × ставка оплаты за месяц | Реализован расчётный режим |
| НДФЛ | Прямой/косвенный ФОТ | ФОТ / (1 − ставка) × ставка | Реализовано |
| Страховые взносы | ФОТ + НДФЛ | Начисленный ФОТ × ставка категории | Реализовано укрупнённо; сверить категории Excel |
| Резерв отпусков | Годовой ФОТ | Годовой ФОТ × 8% каждый месяц | Реализовано; требуется контрольное сравнение с Excel |
| Техника | График техники | Машино-часы × ставка часа | Реализован расчётный режим |
| Материалы | BOQ/первичка | Стоимость МТР без НДС либо физический объём × ставка МТР | Частично реализовано |
| Прямые и косвенные расходы | Параметры + первичка | Фактический месячный ряд статьи загружается как ручное начисление; расчётные статьи остаются доступны для возврата | Реализовано на уровне каждой статьи |
| Финансовый результат | Доходы и расходы | Доходы без НДС − прямые расходы − косвенные расходы | Реализовано |
| Выплаты по расходам | Расходы + срок оплаты | Начисление с применимым НДС, сдвинутое на установленный срок оплаты; ручной факт платежей имеет приоритет | Реализовано и раскрывается до прямой/косвенной статьи |
| НДС к выплате | Поступления, авансы, зачёты, входящий НДС | Исходящий НДС + НДС с авансов − НДС с зачёта − входящий НДС, не ниже нуля | Реализован упрощённый алгоритм; показывать только в составе потока |
| Чистый денежный поток | Поступления и выплаты | Поступления − выплаты по расходам − налоговые выплаты | Реализовано |

## Правила факта и прогноза

1. Количество закрытых фактом месяцев задаётся в версии модели от 0 до 12 и явно показано над каждым месяцем.
2. В закрытых периодах использовать фактические данные первички и платежей.
3. В открытых периодах использовать расчёт по КСГ, BOQ, персоналу, технике и параметрам подрядчика.
4. Факт не должен незаметно заменяться демонстрационными значениями.
5. При отсутствии обязательного источника приложение показывает ошибку или неполноту данных, а не готовый расчёт.
6. Каждая итоговая строка раскрывается до источника, статьи и формулы.

## Состав объединённого раздела

1. Технико-экономические показатели: натуральные физические объёмы из КСГ по десяти ключевым видам работ, основной, вспомогательный и косвенный персонал в FTE, техника в FTE (`машино-часы / 260`). Состав топ-10 определяется по годовой стоимостной оценке, но стоимость в физическом блоке не показывается.
2. Экономические показатели: выполнение по КСГ × BOQ, прочие доходы, прямые и косвенные расходы, финансовый результат.
3. Финансовые показатели: поступления, выплаты подрядчика по каждой статье расходов, скрываемая детализация налоговых выплат, чистый и накопленный денежный поток.
4. Все группы раскрываются независимо; налоговый расчёт по умолчанию скрыт внутри группы.

## Правила представления

- Раздел в интерфейсе называется «Детальная модель».
- Топ-10 работ сортируется по убыванию годовой стоимостной оценки; в физическом блоке показываются только натуральные объёмы КСГ и единицы измерения.
- Доходы раскрываются на те же десять видов работ в денежной оценке и одну строку «Прочие виды работ» для оставшихся сопоставленных позиций.
- Укрупнение цены следует логике НЗС: нормализация наименования и единицы, устойчивый ключ, KQ-1/KQ-2, правила `exact`, `prefix`, `regex`, ключевые слова или ручное назначение. Для расчёта используется фактическая, затем актуальная, затем договорная расценка.
- Несопоставленные и неоднозначные позиции не включаются в ранжирование и доходы до ручного разрешения.
- Для персонала один FTE соответствует полной месячной занятости. Для техники FTE рассчитывается как месячные машино-часы, делённые на 260 часов.
- Нулевые расчётные и отчётные значения показываются прочерком. В полях ввода ноль остаётся числом, чтобы не нарушать расчёт и экспорт.

## Выявленные ограничения исходной книги

- В книге 15 листов и более 60 тысяч формул.
- В XML книги присутствуют повреждённые именованные диапазоны (`#N/A`, `#REF!`), поэтому стандартное чтение книги некоторыми библиотеками завершается ошибкой.
- Для пилота формулы необходимо читать непосредственно из листов, не полагаясь на повреждённые имена.
- Сопоставление BOQ → KQ-2 и классификация персонала требуют отдельной проверки на реальных строках.
- Для исходной книги доступна локальная read-only проверка `scripts/audit_excel_reference.py`: по кэшированным месячным значениям контролируются выручка, прямые/косвенные затраты, финансовый результат, платежи и NCF. Сохранённые значения не являются новым пересчётом Excel; эта проверка не сверяет итог приложения с книгой.
- Первичный просмотр выявил методические различия исходной книги и текущего согласованного расчёта (в частности, резерв отпусков и ставка НДС); до сопоставления входных данных, периодов и правил нельзя объявлять полную формульную эквивалентность или автоматически менять пользовательское правило 8% годового ФОТ ежемесячно.

## Автоматическое подключение BOQ и КСГ (FM-2026-007)

- Приложение автоматически читает `data/sources/boq.xlsx` и `data/sources/ksg.xlsx` при открытии модели; ручная загрузка файла для этого контура не требуется.
- BOQ укрупняется на уровне KQ-2 по логике исходной вкладки `KQ`: код — `BOQ!AF`, приведённый объём — `BOQ!AI`, стоимость — `BOQ!Y`, укрупнённая цена — `SUM(стоимость) / SUM(приведённый объём)`.
- Результат укрупнения выводится на отдельной вкладке приложения `Оценка KQ-2` с объёмом, трудозатратами, машино-часами, стоимостью и ценой единицы.
- КСГ читается построчно: код KQ-2, название и единица работы, затем месячные натуральные объёмы из колонок с датами выбранного года.
- Стоимость применяется скрыто для ранжирования: `сумма месячных объёмов КСГ × укрупнённая цена KQ-2`. В блоке физических объёмов стоимость не выводится.
- В `Детальной модели` показываются натуральные объёмы десяти крупнейших строк КСГ. В доходах показываются те же десять строк и одна строка `Прочие виды работ`.
- Строки КСГ без однозначной оценки KQ-2 не включаются в денежный расчёт молча: их количество отдельно показано на вкладке `Оценка KQ-2`.
