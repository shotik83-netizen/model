# Журнал изменений финансовой модели

## Назначение

Этот файл является постоянным реестром задач проекта. Чат «Журнал изменений» принимает и уточняет задачи, присваивает им номера и ведёт статусы. Основной чат «Финансовая модель» выполняет разработку, проверку и публикацию. После выполнения результат возвращается в журнал.

## Статусы

- `НОВАЯ` — задача записана, но ещё не передана в основной чат.
- `ПРИНЯТА` — требования понятны, задача готова к передаче.
- `В РАБОТЕ` — основной чат подтвердил начало исполнения.
- `НУЖНО УТОЧНЕНИЕ` — без ответа пользователя нельзя выбрать корректное решение.
- `НА ПРОВЕРКЕ` — изменение реализовано и проверяется.
- `ВЫПОЛНЕНО` — опубликовано и подтверждено проверкой.
- `ОТКЛОНЕНО` — задача отменена пользователем с указанием причины.

## Нумерация

Формат номера: `FM-YYYY-NNN`, например `FM-2026-001`. Номер не используется повторно. Несколько требований в одном сообщении разделяются на отдельные задачи, если их можно реализовать и принять независимо.

## Карточка задачи

```text
Номер: FM-YYYY-NNN
Дата: YYYY-MM-DD
Название: краткое действие
Статус: НОВАЯ
Приоритет: высокий / обычный / низкий
Поставил: пользователь

Что изменить:
- ...

Ожидаемый результат:
- ...

Критерии приёмки:
- ...

Зависимости и ограничения:
- ...

Передача в основной чат:
- дата и ссылка/название чата

Результат исполнения:
- коммит или версия
- ссылка на опубликованное приложение
- выполненные проверки
- известные ограничения
```

## Правила работы чата «Журнал изменений»

1. Не изменять код и не публиковать приложение из журнала.
2. Разобрать сообщение пользователя на самостоятельные задачи.
3. Проверить отсутствие дубликатов среди открытых задач.
4. Зафиксировать ожидаемый результат и проверяемые критерии приёмки.
5. Присвоить номер и статус `ПРИНЯТА`, если требования достаточно ясны.
6. Сформировать блок передачи, который пользователь отправляет в основной чат.
7. После отчёта основного чата обновить статус. Статус `ВЫПОЛНЕНО` ставится только при наличии результата и проверки.
8. Если основной чат сообщил о частичном результате, сохранить статус `В РАБОТЕ` или `НА ПРОВЕРКЕ` и перечислить остаток.
9. Не объявлять задачу выполненной только по обещанию или плану.
10. Сохранять историю изменений карточки: дата, старый статус, новый статус, основание.
